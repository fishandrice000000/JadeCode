# s01 - .env 文件解析设计

设计的抽象:

- Env: 提供工具函数, 解析 `.env` 文件, 读入配置.
- AppConfig: 从 `Env` 类中读取配置信息, 后续 Agent Loop 都从一个 `AppConfig` 实例中读取, 确保环境变量在一个实例中完全一致.

## 为什么引入 AppConfig 这一层抽象?

考虑过直接合并进 Env(Env 提供 apiKey/baseUrl 等字段, 全进程共用一个 Env 实例), 最终保留分层:

- **机制 vs 值**:Env 是查找服务(问任何 key, 答案当场算), AppConfig 是启动时定格的值快照. 服务被询问, 值被传递.
- **窄接口**:下游类拿到 AppConfig 只有 4 个确定值; 拿到 Env 则理论上能问任何问题, 且答案可能变化.
- **测试成本**:record 是最便宜的假对象, 一行构造; 下游收 Env 则每个测试都要拼 Map 并记住 key 拼写. 且合并后 `Env.of(Map.of())` 不再安全(apiKey() 会当场抛异常).
- **将来有多个消费者且配置会变**(s06 子代理 / s13 队友运行不同配置):值是值, 可以复制改字段; 全局单例则难以注入另一份配置.
