## 1. 从任务需要出发

一个新任务需要 Java 注释偏好，却不需要饮食偏好。旧知识都在磁盘上，但模型仍需要有人替它挑选。
全量发送正文最简单，却会把无关背景也塞进上下文；本轮选择先发送短目录，请辅助模型选条目，
再把实际选中的原文返回给未来的主请求装配方。

因此两次用途不同的模型请求应分清：辅助请求只回答“选哪些知识”，主请求才负责“怎样完成当前任务”。
当前代码实现的是前者与背景构建，后者的实际注入属于后续接线，不能把一个字符串的生成当成整个能力已启用。

## 2. 推荐阅读顺序

1. [MemoryRecallService.recall](../../../src/main/java/com/jadecode/memory/MemoryRecallService.java)：
   先看方法 JavaDoc，再沿一次请求读三个阶段：固定记录快照 / 构造目录、辅助选择、生成带来源的背景。
   暂时把 helper 当成它们已声明的契约，不先逐个刷完。
2. 同文件的 SELECTION_SYSTEM、selectedIndices 与 RecallResult：
   看辅助模型有多大决策权、为什么回传索引、合法空选择与失败各代表什么。
3. [MemoryStore.listRecords](../../../src/main/java/com/jadecode/memory/MemoryStore.java)：
   看知识来自哪个工作区、何时重新读取、哪些材料算作可召回记录；再按需看 parseRecord。
4. 回到 keywordSelection 和背景预算段：看没有理想选择时的有限替代，以及大记录如何占用共享原文额度。
   不要求背词正则、集合 API 或字符下标；只有它们影响 Agent 的信息边界时才深入。

## 3. 读代码时保持这些区别

- 本机扫描会读完整文件；“目录 / 正文分离”限制的是发送给模型的内容，不是保证磁盘只读取选中文件。
- 记录快照固定一次召回的索引关系，不提供并发文件事务，也不证明知识仍符合当前现实。
- 模型决定相关性，harness 只接受本次目录中的索引，不能让选择回复成为任意文件读取指令。
- 合法 [] 代表模型没有选中；usedFallback=true 代表选择调用或回复验证失败。
  降级依旧可能为空，它不是“失败就全部加载”。
- 关键词只用于召回失败降级，没有提取模块或按临时词拒绝保存的逻辑。
- background 是 source / content / truncated 对象的 JSON 数组，不是 user 命令、工具结果或无损全库备份。
- 20000 限制原文总量（含 frontmatter），不包含 JSON 包装 / 转义，不是每条各享有 20000，也不是 token 保证。
- 来源相对于绑定工作区。后续回查必须沿用该工作区与权限约束，不随某次 Bash 的临时 pwd 改变。
