# 阶段三：工程组织、可验证性与文档一致性

## 工程组织评价

当前 73 个产品 Java 文件、约 10,957 行（含注释/空行），Maven 单模块。按能力建包基本合适，课程进度放在 jobs/notes，没有把 s01–s17 直接变成生产模块。Context 的门面和内部策略、Memory 的服务分工、Tool 与 Task/Cron 领域的分离都值得保留。

主要组织问题是 tools 混合了模型适配和进程基础设施，以及共享执行类型把多个包绕回 agent。具体调整方案见 [ARCH-019 包专题](02-modules/package-architecture.md) 和 ARCH-011。没有证据要求拆多模块、采用 Spring、添加外部 MQ 或先建立全套抽象基类。

## ARCH-014：新可靠性机制缺少可留存、可重复核验的自动化证据

**P2；有依据的潜在风险；分类：长期验证与维护风险。**

源码中有 40 个测试 Java 文件，其中两份是假客户端辅助；静态统计 331 个 `@Test` 声明，**不是本轮运行结果**。分布为 context 116、agent 48、safety 31、subagent 30、tools 28、skills 26、messages 15、Main 15、config 13、todo 9。现有测试大量覆盖压缩策略和同步旧入口，但没有专门的 memory/tasks/cron/cli/SessionRuntime/BackgroundManager 保留测试文件。Main 装配测试覆盖工具表和部分集成，不能替代这些机制的故障路径。

反向检查：任务单保存了临时离线程序和真实 CLI 验收记录，不能说新模块从未验证；用户明确要求不主动新增单元测试。问题是临时验证源码已清理、场景不直接作为可重复交付物保留，后续包迁移或生命周期修改较难机械复查。331 条存在也不能证明今天执行通过。

**具体设计**：在未来获准实施具体变更时，优先保留精简的“场景输入、预期状态、关键观察项”，复用 Scripted/RecordingLlmClient 与可注入 Clock/临时工作区。先保护首回复确认、通知领取/确认/归还、满队列、晚到回复与退出这几个跨模块边界。不要求本次新增 JUnit，不扩大成完整测试矩阵；若将来要增加永久自动化，必须按用户当前规则先说明必要性并获得明确同意。

收益是让重构的保行为证据可复用；范围工程验证资产、宿主依赖注入和验收清单；成本中；回归风险主要来自测试夹具依赖提示词措辞/私有反射，应该按机制观察而非复制实现。P2 因已有历史验证与可测试入口缓解，不能把缺少某测试文件等同于产品错误。

源码证据：`src/test/java/com/jadecode/llm/RecordingLlmClient.java:22–35`、`src/test/java/com/jadecode/llm/ScriptedLlmClient.java:18–26`；`src/test/java/com/jadecode/MainCompactionAssemblyTest.java:63–130,199–428`；`src/main/java/com/jadecode/cron/CronScheduler.java:46–60` 的 Clock 注入。历史验证证据为 `docs/jobs/s12/session-event-refactor.md:137–153`、`docs/jobs/s12/terminal-and-acceptance.md:44–79,95–104`，本轮仅阅读，未复跑。

## ARCH-020：现行使用和学习入口存在少量可定位漂移

**P3；已证实；分类：实际文档与能力边界差异。** 本项只检查架构相关描述，不做写作质量审计。

| 文档声称 | 源码实际行为 | 差异和影响 |
| --- | --- | --- |
| README 配置列表包含 FALLBACK_MODEL_ID（`:71`） | AppConfig 只有一个模型，SDK 固定使用该 model；src 无该变量读取 | 用户配置备用模型不会生效，可能误以为失败后会切换 |
| 当前事件学习入口称审批答复带 ID，并要求解释带 ID 命令（`docs/notes/s12/session-event-runtime-review.md:45,83`） | ConsoleInput 只接受 pending 时的 y/n/空行拒绝，不生成 ID；最新任务单已明确取消 ID | 学习者会寻找不存在的审批路由；应更新题干且保护已有答案 |
| s01 学习说明称 stop_reason 只是调试信息、内容足够决定循环（`docs/notes/s01/agent_loop.md:7–14`） | 当前实现确实不保留该字段，但无法区分输出截断与正常完成（ARCH-003） | 这是对实现取舍的过强解释，容易让学习者把协议缺口当普遍原理 |

反向检查：s11 与原 s12 指南已有版本提示，旧 CronRuntime/runScheduled 记录不能算当前源码未实现的缺陷；s09 概念笔记和 s10 尚未验收文字是带日期的阶段快照，不要求机械刷新所有历史记录。README s15 类名处于未来章节映射表，不据此声称已有这些类。最新 terminal-and-acceptance 的历史带 ID 文字后有明确新版裁决，不能只摘旧段落说它自相矛盾。

**具体设计**：更新现行 README 的实际配置表、当前学习入口与普遍化协议解释；历史任务保留，只补明确版本路由。采用“配置名 → 读取位置 → 是否生效”的短表，不自动实现备用模型功能来迎合旧文档。问题修复只更新题干，不覆盖用户答案。

收益是避免误配和错误学习；范围上述三份文档及当前入口路由；成本低；兼容风险是笔记答案保护和历史事实丢失。P3 因不直接改变执行，但会误导使用和维护。源码证据：`config/AppConfig.java:17–61`、`llm/AnthropicSdkLlmClient.java:40–45,74–79`、`cli/ConsoleInput.java:85–110,188–199`；最新裁决 `docs/jobs/s12/terminal-and-acceptance.md:88–94`。
