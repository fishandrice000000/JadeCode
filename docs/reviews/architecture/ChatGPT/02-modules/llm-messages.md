# 模块审查：模型接入与消息协议

## 机制和合理之处

模型请求使用产品自己的消息、工具调用和结果记录，SDK 转换集中在一个适配器。工具调用 ID 在构造时检查非空；历史入口检查相邻交换、顺序、数量和重复 ID。父循环在执行工具前检查回复角色和调用 ID，避免发现非法回复时已经产生工具副作用。封闭的三种 content block 对当前文本与工具能力足够，不必为了未来多模态立即扩展。

消息 record 并不自动深度不可变：消息列表及工具 input 的 JSON 仍可修改。目前单消费者和局部重建降低了实际风险，但异步事件不能据此被视为深拷贝快照。共享 JSON mapper 的忽略未知字段策略适合消息兼容；任务等存储另做严格字段检查，不能笼统说所有持久化都宽松。

证据：`messages/ToolExchangeProtocol.java:35–38,93–151,165–240`；`messages/Message.java:22–59`；`messages/ToolUseBlock.java:22–30`；`llm/AnthropicSdkLlmClient.java:74–127`；`util/Json.java:14–16`。相对路径前缀均为 `src/main/java/com/jadecode/`。

## ARCH-003：模型为什么停止的信息丢失，无法区分结束和截断

**P1；已证实（元数据被丢弃）；分类：实际协议设计缺陷。具体 provider 触发情况待验证。**

适配器只返回消息和 token 用量，没有保存停止原因；运行器将无工具回复经过 Stop 检查后作为完成。于是达到生成上限但仍有文本的回答，与正常结束在产品模型中完全相同。子代理也无法区别；定时交付则可能在不完整回复上确认送达。问题不是模型说错一句话，而是程序根本没有表达这种区别的字段。

反向检查：上下文超限补救只处理请求抛出的异常，无法解释 HTTP 成功但输出被截断。Memory 的 JSON 校验能拒绝不完整数组，是局部缓解；不能保护主回答。适配器对未知块会告警并跳过，如果全部被跳过，父执行器仍接受空 assistant。摘要服务还把无正文的结果转换为 `(empty summary)` 并允许替换历史，归档可回读但并未阻止有效上下文退化。

**具体设计**：给模型响应增加独立于 SDK 的结束原因及完整性信息。适配器保留已知原因，对未知原因保留原始值。正式请求只有“可继续的工具回复”或“完整的最终回复”才能推进对应状态；输出达上限进入有界续答或明确的不完整结果，不能直接标 Completed。摘要要求 assistant 纯文本且有实质内容；无效时保留旧历史并明确失败/降级，不能把占位文字当成功摘要。定时“有效回复”的判定在这层统一，仍与业务成功分开。

收益是消除一类假完成和信息丢失；范围适配器、响应模型、父子循环、摘要服务与定时确认；成本中；兼容风险是不同兼容 endpoint 的结束原因不完全一致，需要 unknown 分支和离线响应样例。P1 因为影响任务完成与交付确认两个核心契约。

源码证据：`llm/ModelResponse.java:11–17`；`llm/AnthropicSdkLlmClient.java:163–180`；`agent/AgentLoop.java:282–288`；`agent/SessionRuntime.java:267–269,296–306`；`subagent/SubagentRuntime.java:269–283`；`context/HistoryCompactor.java:198–213`。反例核查：`src/test/java/com/jadecode/context/HistoryCompactorTest.java:226–247` 明确期待跳过非文本并接受空摘要，说明这不是遗漏的隐藏校验。

## ARCH-009：SDK 转换没有完整保留工具声明的 schema

**P2；已证实；分类：实际接口缺陷。**

任务工具和 cron 工具声明了根级别“不接受额外属性”，适配器只重建 type、properties、required，把其它根字段丢掉。模型收到的约束因此弱于工具自己声明的约束。属性内部的 items、pattern 等仍被整体转换，不能把它误写成全部复杂 schema 都丢失。运行时严格检查还能拒绝额外参数，安全影响有限，但更容易出现模型看似合法、执行又被拒绝的交互。

**具体设计**：由 LLM 请求持有只读的工具定义（名称、描述、完整 schema），SDK 层对整份 schema 做保持字段的转换；若 SDK 类型无法原样承载某字段，明确失败或显式兼容转换，不静默降级。执行对象仍留在工具运行层。先修保真，再决定是否拆定义接口，不为这一点建立多后端框架。

收益是声明与实际 wire 一致，也减轻 LLM 层对执行工具的依赖；范围 Tool 定义及适配器；成本低至中；风险是 endpoint 对某些 schema 字段的支持差异。P2 因为当前运行时校验已有兜底。

证据：`tools/TaskTools.java:113–128`、`tools/CronTools.java:60–63`；`llm/AnthropicSdkLlmClient.java:131–157`。本轮未调用真实 endpoint，建议以后用序列化的请求样例核对字段，不需要真实模型调用才能检查这一点。

## 结论

消息配对校验已经比较扎实；优先补模型响应的完整性契约，然后修 schema 保真。SDK 的具体默认超时、内部重试和资源线程未检查第三方实现，本报告不声称它们缺失或泄漏。Review：**Blocking（ARCH-003 对长期可靠性的边界）**，不代表本轮已运行复现。
