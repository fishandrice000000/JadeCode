# 模块审查：会话、任务执行与事件

## 机制和合理之处

会话运行器保存历史、当前任务和运行状态。执行器完成模型请求、整批工具和压缩步骤，结果交回运行器统一采用。人工请求和定时请求走同一队列；后台结果另存，只有通知信号进入唤醒机制。等待前先读修订号、再检查结果，可以避免“结果刚到，消费者却睡下去”的丢唤醒。

失败语义也有明确区分：工具返回普通错误交给模型处理；执行意外异常则补齐整批结果并结束任务。首回复前的定时失败恢复原历史，其它失败保留真实步骤，不自动撤销外部副作用。关闭会话会先禁止工具和停止 shell，再完成 future，避免回调拖延停止。

源码依据：`agent/SessionRuntime.java:204–309,322–417,509–529`；`agent/SessionInbox.java:38–103`；`agent/AgentLoop.java:253–375`。本报告的 `agent/...` 均位于 `src/main/java/com/jadecode/`。

## ARCH-008：父任务没有整体执行预算

**P1；有依据的潜在风险；分类：可靠性风险。**

当前每次明确的上下文超限最多补救一次，但父任务没有总轮数、总模型请求数或总时长限制。模型若反复调用已拒绝的工具、持续运行短命令，或 Stop 一直要求继续，就会一直占据会话。后台命令的 120 秒超时不能限制这条循环；压缩反而允许它更久地继续。后面的人工和定时任务只能排队，直到满额拒收，用户还会持续消耗模型额度。

反向检查：子代理已有 30 轮上限；关闭会话能阻止后续工具，队列也有 64 项限制。这些能控制局部资源，但无法让一个仍在正常回复的父任务主动让出位置。未证明真实模型已经进入死循环，也不把长任务本身判成错误。

**具体设计**：由运行器给每个执行任务创建预算对象，分别记录正式轮次、所有模型调用及截止时间；摘要、召回和子代理消费同一任务的总额度，同时保留各自局部限制。在安全边界耗尽预算时进入明确的 STOPPED 结果，关闭必等命令、保留历史和已发生副作用，完成 future 并领取下一项。不要借用“上下文超限异常”表达预算结束，也不要自动从头重跑。先开放适合个人使用的轮数和时间设置，不必上复杂计费系统。

收益是限制失控成本与队头阻塞；影响运行器、父子执行器和辅助模型服务；成本中；回归风险是过紧预算中断正常长任务，需要可配置及清楚的停止说明。列为 P1，因为它影响整段会话可用性和真实 API 成本。

证据：`agent/SessionRuntime.java:260–309` 的无限任务循环；`agent/AgentLoop.java:256–288` 的局部重试；`subagent/SubagentRuntime.java:41,184,354–355` 的局部轮次限制。待验证目标：用受控连续工具回复观察预算耗尽后的下一任务推进，本轮未执行。

## ARCH-011：稳定执行契约被放进具体运行器与松散 hook 参数

**P2；可选优化；分类：架构优化机会。**

可信任务身份由 agent 定义，却引用 safety 内的审批接口；safety 和工具又反向引用任务身份。执行器还向运行器暴露具体后台管理器和 cron 对象，运行器再把执行结果和文本输出拼接起来。当前能够工作，不能把包环说成运行死锁；但添加新入口或非终端宿主时，需要把这些具体依赖一起带走。

另一个隐式约定是权限作为普通 PreToolUse hook 注册：事件名和参数键都是字符串，handler 强制转换参数；任何较早的非 null 返回都会短路后续 handler。Main 的当前顺序正确，父子工具实际受检，因此不认定生产路径遗漏权限。但新的装配可以创建空 hook 表并执行工具，必选授权与可选日志在接口上没有区别。

**具体设计**：建立很小的执行契约包，只放任务身份、取消信号和审批端口；safety 实现权限判断，工具依赖契约而不依赖调度器。将“检查并执行一项工具”收敛到必经执行服务，构造时必须提供权限策略；日志、展示与扩展 hook 放在该服务外侧。运行器继续拥有历史，不将所有步骤异步化。事件参数逐步改为有类型的载体，优先覆盖权限和工具结果，不必一次改完所有 hook。

收益是减少装配顺序依赖、让安全入口可见；范围 agent/safety/tools/Main；成本中；风险是迁移时改变 hook 顺序或重复执行，需要逐批保持现有 wire 格式。P2 是因为当前装配可解释，收益主要体现于扩展和维护。

证据：`agent/ExecutionContext.java:7,24`；`safety/PermissionGate.java:108–111`；`tools/Tool.java:74–75`；`agent/AgentLoop.java:174–186,317–338`；`safety/Hooks.java:21–41,92–103`；`Main.java:208–217`。空 hook 的用途还可见 `src/test/java/com/jadecode/agent/AgentLoopTest.java:39–55`，它证明该 API 可绕开装配，不证明当前 CLI 被绕开。

## 结论

会话所有权和队列划分值得保留。主要短板是缺少任务级上限和必选执行契约，而不是缺少更复杂的调度框架。Review：**Non-blocking（结构），ARCH-008 应优先治理**；该结论不是动态验证通过。
