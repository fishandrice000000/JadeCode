
# JadeCode 每章(s01-2 起沉淀,共 17 章)的固定协作节奏

0. **任务拆解(我)**:细粒度 task + 状态维护。
1. **概念先行(用户)**:用户读课程章节,带问题来问;我答疑并对齐 DeepSeek 文档的 wire format。
2. **发布作业(我)**:文件清单 + 每类字段/方法签名/注解 + 测试断言点 + 预告 1-2 个坑。**只写规格,不写实现。**
3. **写代码(用户)**:主类用户写;卡在小方法上求助时我才给实现讲解。
4. **Review(我)**:读实际代码再评论;肯定好选择 + 指出问题;不擅改用户文件(连多余 import 都让用户自己删)。
5. **测试(我写,基于用户实际代码)**:先读全部主类再落笔;用户手动跑 `mvn -q test`(用户偏好自己执行验证命令,会拒绝我的 Bash 调用)。
6. **Git 提交(规则驱动)**:我出方案 → 用户审批(可能驳回重拆)→ 执行时每批精确 add 具体路径 → `git diff --cached --stat` 核对 → commit → 总核。拆分标准:**按依赖顺序,每个提交独立可编译**;一次提交只做一件事。
7. **收尾**:TaskUpdate 完成;stray 文件只上报不擅动;预告下一步。
