# 统一会话事件处理而不全面异步化

2026-10-16，事件化重构讨论确认：用户请求、定时任务、工具结果、后台通知与 Stop 续跑通过统一的事件处理规则进入会话历史。统一事件处理不要求模型调用与普通工具全部异步化；普通调用仍可同步执行，工具批次完成后统一回灌结果，真正需要异步执行的命令继续使用后台任务机制。

不全面异步化可以避免仅为统一入口而引入所有操作的并发、取消与晚到结果管理。统一入口不能破坏工具交换配对，也不能将权限拦截降为模型可忽略的提示文本。

每个任务由 Harness 标注可信来源，审批资格不再依赖执行线程身份。人工发起的任务可以通过统一终端输入入口请求审批；定时任务需要交互审批时直接拒绝；子代理继承发起任务的审批边界，模型不能修改来源。命令拒绝表与路径围栏保持不变。

收件箱只保存在进程内，不增加会话历史恢复、普通请求队列恢复、执行进度恢复或后台进程恢复。已有定时定义及 durable 待交付记录保持持久化；这不意味着所有会话事件都需要落盘。

定时任务继续在模型首次有效正式回复时确认交付，而不是入队时或业务成功时确认。首回复前失败沿用已有有限退避重投；首回复后不自动重投整项业务，避免重复副作用。确认与执行无法构成任意外部操作的原子事务，因此不承诺恰好执行一次。

任务已经开始后，若模型执行链在既有补救后最终失败，运行器报告失败并结束本次执行，终止仍在运行的必等后台命令，释放位置以领取下一任务。保留真实历史及已发生的副作用，不自动重跑整个任务。明确脱离当前任务的命令继续按会话级通知规则处理；退出 CLI 时才统一清理。这与单条命令失败交给模型处理的策略不同。

人工请求与定时任务按进入收件箱的顺序领取，不按来源插队，不抢占当前任务。工具结果、后台结果和 hook 续跑属于当前任务的继续输入，不参与新任务的 FIFO 排队。等待后台结果时可以展示模型文字，但标为进展，并由 Harness 显示等待状态；不能凭模型自称完成就结束任务。

生产者只提交带可信来源和关联身份的事件，不直接修改会话历史。会话运行器作为单一消费者，拥有历史及当前任务状态，决定领取、继续、等待、结束、交付确认和失败收尾。执行器负责模型、工具和压缩等执行流程，不管理人工与定时两套入口，不接管整个会话的排队和重投。三类职责明确区分，避免把所有功能堆到一个消费者类中。
