# 区分后台执行与任务完成依赖

2026-10-16，事件化重构讨论确认：首要目标是让任务生命周期容易理解，以统一事件处理为方向，不默认增加其他调度能力。同一会话的新请求排队；当前任务等待所需后台结果时仍占据执行位置，不领取下一任务。

后台执行不等于允许当前任务提前结束。Bash Tool 将通过显式属性区分“任务必须等待的后台命令”和“脱离当前任务的后台命令”，不通过命令文本猜测依赖关系。前者的结果到达后应能恢复当前任务，而不是必须等待新的用户请求。

所有后台命令都脱离任务会使依赖构建、报告等结果的任务过早结束；所有后台命令都必须等待又不适合长期运行服务，因此将执行方式与任务完成依赖分开。

后台执行时使用 `wait_for_completion` 表示任务完成依赖，省略时默认 `true`；`false` 才明确脱离当前任务。`true` 不改变工具立即返回启动回执的方式，后续等待由任务运行器管理。

多个必等后台命令按已到达结果逐批恢复当前任务，不强制等全部命令完成才恢复。在安全的请求边界合并当时已经到达的结果，不为每条事件单独请求模型，也不并发请求模型。模型处理后若暂无操作且仍有必等结果未到，任务继续等待，不反复调用模型询问进度。

必须等待的命令失败或超时同样产生完成结果，交给模型结合任务目标决定报告、修复或重试。Harness 不自动重跑命令，也不将单条命令失败直接判为整个任务失败；等待完成不等于等待成功。

脱离当前任务的命令完成后形成会话级通知，保留来源任务与后台命令标识。不恢复已结束的原任务，不主动唤醒空闲模型；下一次正常请求在安全边界带入，并明确通知来源，不替换当前目标。

退出 CLI 时终止本会话仍在运行的全部后台命令，包括明确脱离当前任务的命令。脱离任务不等于脱离 CLI 生命周期，本次不增加守护进程、跨重启恢复命令或退出前排空任务的能力。
