## 第一轮已确认的选择

### Q1：替换旧交互界面

默认使用新 TUI。旧交互模式弃用，不提供重新启用的接口，也不继续维护。
不采用参考文档中“先增加 --tui、默认仍走旧 REPL”的发布方式。
`run` 和非交互输入的输出约定已在 Q6 单独确认；保留非交互执行不是保留旧 REPL。

### Q2：采用 Pi 式内联重绘

采用主屏内联形态。用户选择允许在需要重排历史时清屏、清空 scrollback 并重放会话内容。
这可能清除进入 JadeCode 前的终端滚动历史，不能同时承诺永久保留原 shell 输出。
窗口尺寸变化、旧条目展开或主题变化是否需要整篇重绘，以最终渲染策略和实际源码核对为准。

### Q3：遵循 Pi 的 TUI 实现思路

忠实遵循 Pi 的 TUI 实现，不只模仿标签和颜色。将终端输入、界面状态、组件渲染和终端写入
作为一套完整前端设计；Pi 的 JavaScript/TypeScript 实现细节需要映射到 Java 21。
具体事件接缝仍需根据 Pi 与 JadeCode 实际源码确定；本项不等于授权重写 Agent 调度、权限策略、
Team 通信、消息协议或压缩算法，也不表示参考文档中每段示例都已成为确定的 API。

### Q4：首版功能范围

包含：

- 消息流、Leader 流式正文与接口提供的思考内容。
- 调用与结果合并的工具卡片，以及输出折叠。
- Markdown、代码块和基本代码配色。
- 多行编辑、粘贴、输入历史及待发送提示词。
- 工作状态、页脚与审批界面。
- 主题与帮助／命令选择器。

不包含会话树、图片、复杂鼠标操作、运行期模型切换或思考模式切换。
页脚只显示真实取得的数据，不伪造费用或缓存统计。

### Q5：支持范围

仅承诺 Linux 本地与 SSH 常见终端，暂不做更广泛的平台适配。
中文、多行粘贴、窗口缩放与无颜色模式属于这一范围内需要验证的行为。

## 第二轮已确认的选择

### Q6：非交互执行

`jade repl` 必须连接真实终端，不满足时明确提示，而不是降级运行旧 REPL。
`jade run "任务"` 保留一次性文本输出与重定向能力，不启动 TUI，不作为旧交互模式维护。

### Q7：不引入单轮取消

本次不引入取消当前执行但保持会话存活的能力。用户希望先评估该能力对 JadeCode 的影响，
不能仅为了复制 Pi 的 Esc 行为而顺手扩展 Session 的取消契约。
Esc 可以处理界面选择与焦点，但不能宣称已经中止当前 Agent、网络请求或工具。
会话整体退出仍沿用现有关闭职责；具体按键安排见 Q13。

### Q8：支持基本鼠标点击

支持左键展开／折叠单个工具结果或思考块，不引入拖拽和复杂鼠标导航。
Ctrl+O 全局展开工具卡、Ctrl+T 全局切换思考显示与单卡点击共同保留。

### Q9：多 Agent 沿一条消息流展示

消息流按事件到达顺序排列，每张卡明确标注来源。工具结果更新对应调用卡，不再新增一份。
队友工具默认折叠，报告显示摘要；状态区显示成员工作状态，不增加队友聊天窗口。
隐藏队友思考不影响模型协议中的思考保存和回传。

### Q10：审批使用选择界面

用户明确覆盖上一轮建议：TUI 审批提供“同意／拒绝”两个可选项，不要求在提示词输入区
键入 y/n。审批请求仍逐项绑定实际操作，多份请求排队，不改变权限策略。
未提交提示词与光标需要保存，审批完成后恢复；选项的默认状态、键盘确认及 Esc 语义
已在 Q12 明确，不能把普通输入或旧的 Enter 按键误当作同意。
本项针对 TUI；非交互 run 在实际终端可用时如何回答审批，沿已有文本执行契约处理。

### Q11：界面记录不随模型压缩删除

本次运行中，界面保留原消息、原工具卡片等记录，压缩后另显示提示。
模型继续使用压缩后的会话历史，两者不要求保持相同长度与内容。
本项不新增退出后的历史恢复，也不改变现有压缩算法。

## 第三轮已确认的选择

### Q12：审批确认方式

审批出现时，同意与拒绝都不默认选中。用户用左右方向键或 Tab 选择后按 Enter 确认，
也可以直接鼠标点击选项确认。没有选择时，Enter 不作答；Esc 不自动拒绝。
草稿和光标完整保存；多份审批逐份显示，每份都需要重新选择，不能复用上次答复。

### Q13：退出与界面快捷键

- 编辑时，Ctrl+C 第一次清空草稿，500ms 内再次按下退出整个会话。
- 编辑器为空时 Ctrl+D 退出；非空时按向前删除字符处理。
- Esc 只关闭可取消的帮助、选择器或补全，不中止 Agent。审批按 Q12 保持待答。
- 审批期间，第一次 Ctrl+C 只提示退出方式，不删除保存的草稿；连续第二次退出，
  并拒绝所有未答审批。
- 不保留 q／exit 整条输入退出的特殊语义；它们不再被 CLI 截获成退出操作。
- 整体退出仍关闭 Team 及会话拥有的命令，不新增单轮取消能力。

### Q14：主题偏好持久化

提供深色与浅色主题。用户明确选定的主题保存到 `~/.jadecode/config/tui.json`，下次启动使用。
该文件只保存前端偏好，不保存凭据、模型配置、会话正文或草稿；尊重 NO_COLOR。
本轮规划不创建机器级配置文件，实现后在实际保存偏好时按该路径处理。

## 沿用的现有用户交互约定

- Enter 提交，Alt+Enter 换行；粘贴多行文字不自动提交。
- Agent 忙时，多次用户输入合并为待处理缓冲；输入区为空时再按 Enter 升级同一缓冲，
  不是重复投递一份消息。
- 审批必须明确选择结果；TUI 按 Q10 使用同意／拒绝选项，不再用提示词输入作 y/n 答复。
  空 Enter 不应自动作出审批决定。
- 仅 Leader 展示思考；队友与一次性子代理不展示思考，但不丢弃协议要求保留的思考块。

以上由原契约及本轮明确变更组成。其它行为需要改变时必须明确讨论。

## 整体实施方案（已确认）

### 1. 保留什么，替换什么

保留 SessionRuntime 的历史所有权、Inbox 消费与缓冲升级、完整工具批次、必等后台结果、
Team 派工和报告、权限裁决、Memory 时机、压缩算法，以及模型思考块的协议保存与回传。

替换交互模式中的 LineReader、PrintAboveWriter、Status 半行预览和零散打印组合。
JLine 继续作为终端适配组件，提供原始输入、尺寸与终端能力；不再由 LineReader 编辑输入。
新编辑器和新渲染器共同组成唯一的交互前端，不增加 --tui／--legacy／--plain 切换接口。
run 使用独立的非交互文本适配，不为了保留 run 而继续维护旧交互前端。

### 2. 分层与线程职责

```text
现有 Agent / Session / Team / 后台服务
             │ 只读展示通知、流式片段、审批申请
             ▼
         CLI 桥接层 ────┐
                       ▼
终端输入读取 ────→ 界面事件队列
                       │
                       ▼
                 单一界面线程
                       │
          修改界面状态 → 组件按宽度产行
                       │
                       ▼
             内联差分渲染 → 终端
```

- 输入读取线程只解码按键、粘贴和点击，并投递事件，不修改组件或写屏幕。
- 界面线程独占界面状态、布局、焦点、光标与终端输出；不能等待模型、工具或审批答案。
- 现有 Session 消费线程继续推进 Agent，通过桥接投递不可变的展示数据，不触碰组件。
- 界面队列不替代 SessionInbox。提交提示词仍调用 submitUser，升级缓冲仍调用
  promoteUserBuffer；展示事件不能自行插入模型历史或调用模型。
- 普通刷新请求合并到约 16ms 一帧；按键尽快处理；无更新时不空转。
  流式文本不能丢片段，合并刷新不等于丢弃内容；过期动画和尺寸事件可以合并。

建议组织为 `tui.core`（终端、输入、行与差分）、`tui.components`（编辑器、Markdown、列表）、
`tui.theme`（主题）与 `cli.tui`／`cli.tui.bridge`（JadeCode 会话界面与接入）。
通用 TUI 组件不引用 Session、模型协议或 Team。若核心需要新增观察接口，放在中立的执行
契约一侧，不让 Agent 依赖 CLI；不建立一套能够反向调度 Agent 的新事件系统。

### 3. 屏幕布局与操作

从上到下采用 Pi 的内联纵向布局：

1. 启动信息与界面会话记录：用户消息、Leader 正文／思考、工具卡及带来源的通知。
2. 待发送提示词区：显示尚未消费的同一缓冲批次，升级插入时更新标记而非再画一份。
3. 工作状态与成员状态：由真实状态变化更新，工作状态可放在编辑器上边框。
4. 编辑器；打开帮助、主题或审批时，输入区临时由对应组件接管。
5. 页脚：目录、Git 分支、模型及已经实际取得的 token 用量。

编辑器支持多行、软换行、光标移动、删除、撤销、输入历史、括号粘贴和 Alt+Enter。
大段粘贴可按 Pi 方式折叠成编辑占位，提交时必须还原原文，不能把占位文字发给模型。
中文、组合字符和 emoji 的光标、删除与换行不能简单使用 UTF-16 字符数。

工具默认折叠，通用结果预览前十行；针对文件读取、修改、bash、任务／Team 工具提供
必要的参数摘要和结果显示。Ctrl+O 全局切换工具展开，左键切换单卡。
思考默认显示，Ctrl+T 全局切换，左键控制单段。队友和一次性子代理不显示思考。
不为尚未完成的工具参数或输出增加可执行操作；工具仍等待完整回复和权限校验。

帮助与主题选择器替换输入区，退出后恢复草稿与光标。命令补全只列真实实现的前端操作，
例如 /help、/theme，不展示假的模型热切换、会话树或单轮中止选项。
审批显示来源、工具、参数与理由，以及同意／拒绝选项，遵循 Q12，不用文字 y/n 作答。

### 4. 保证状态不会说谎

现有接口不完全等同于 Pi：工具返回 String，ToolResultBlock 没有 is_error；ModelResponse
有 input/output token，但当前执行器没有把它们交给展示层。这些差异需要最小观察适配，
不能靠猜测补齐。

- 工具键包含会话／Agent 身份、请求或批次身份、一次性子代理调用身份及工具调用 ID，
  避免不同 Agent、不同请求的同名调用串卡。展示用身份不能改变 ExecutionContext 的任务
  身份、权限来源或后台归属。
- 工具被拒绝、未知、意外异常、未执行及正常返回都有明确的卡片收尾；不只依赖 POST hook。
- 拒绝和异常等程序确知的失败使用明确状态。仅有普通 String 返回而无结构化结果时，
  使用中性的“已返回”，不能把它等同于业务成功；不因正文以 Error: 开头就断定失败，
  文件原文和成功命令也可能合法包含这种文字。本次不为配色重写所有工具或改变 wire format。
- 后台结果可使用已有 status／exitCode，Team 任务可使用真实任务状态；“命令成功”仍不等于
  “整个目标完成”。状态栏不能把队友的结束事件当作 Leader 已空闲。
  后台展示不得覆盖当前已用于 Inbox 投递的 onResult 监听器，也不得通过取走结果计算数量。
- 正常结束、执行失败和会话关闭都更新前端状态，不只等待正常路径上的 TURN_END。
- 响应流失败保留已显示片段并明确标为不完整，不写入半份模型消息，也不重播成功正文。
- token 用量来自实际响应观察，不从字符数伪算。首版明确标为“Leader 正式请求累计输入／输出”，
  不冒称包含队友、子代理、Memory、摘要与辅助审批的全会话用量。SDK 当前在缺少 usage 时
  填零，接入时须区分未报告和真正的零，不能把缺省值当实测值。没有真实统计来源的费用、
  缓存命中率及上下文百分比不展示；不为填满页脚而引入模型目录或计费系统。
- 现有直接 System.out／err 输出使用按行路由作为兼容兜底；关键消息优先走结构化桥接。
  兜底无法确定来源时标为系统信息，不猜 Agent 身份。
- 只读观察通知与具有短路权限的检查 hook 不混用：显示端异常不得把已经完成的工具变成
  执行失败。若整个前端已经无法正常运行，则明确报错并按现有职责关闭会话，不能让无法
  显示审批的 Agent 无人可见地继续运行。

### 5. 渲染、历史与终端安全

使用结构化样式行，统一计算显示列宽，最后编码终端样式，避免换行时切断 ANSI 或字素。
InlineRenderer 维护上一帧、视口起点、硬件光标和尺寸；追加时滚入终端历史，局部变化只
重画对应区间，必须重排时按 Q2 清屏和 scrollback 后重放。

已完成条目按宽度、内容版本和主题缓存，流式部分单独更新；不每帧重新解析全部 Markdown，
不复制一份新的完整历史。界面记录独立于模型压缩，当前承诺保留到本次进程结束；不静默
截掉用户记录，不新增数据库、会话恢复或另一套归档系统。

模型、文件、工具与日志中的原始终端控制序列不能作为渲染指令执行。界面自己生成的颜色、
光标及鼠标控制与不可信正文分开；支持无颜色模式和终端能力降级。
基本鼠标点击只作用于当前可寻址的可见区域，不假装能够定位终端滚动历史中的任意旧行。

### 6. 主题、启动与退出

深色／浅色都通过主题 token 取色，不能在组件内部散落固定 ANSI 色码。
只在用户明确选择时保存主题；按 Q14 的路径保存版本和主题名，写入采用同目录临时文件后
替换，避免中途退出留下半份 JSON。配置无效或无法保存时明确提示，不让主任务因此失败。
不得顺手读取或修改模型凭据、其它机器级配置，也不把运行期偏好文件加入 Git。

退出先停止接收新输入、拒绝全部待答审批，再按现有职责关闭 Session、Team、cron 和命令。
清理工作不在界面线程持锁等待各会话退出。清理阶段前端仍可显示状态；之后停止输入读取、
结束渲染并恢复输出流、终端属性、光标、
鼠标与括号粘贴设置。初始化失败也要恢复已经修改的设置。
晚到的输出不得写进已关闭的界面；网络请求仍在返回时如实提示，不宣称已强制取消。

### 7. 文件范围

- `cli/ConsoleInput.java`、`TerminalDisplay.java`、`CliOutput.java`、`CliHooks.java`：
  迁移后删除旧交互职责；run 仍需要的文本职责应拆成明确的文本适配，不留旧交互启动路径。
- `bootstrap/JadeCodeFactory.java`：注入新展示与审批适配，提供准确身份，不依赖 CLI。
- `agent/AgentExecutor.java`、`session/SessionRuntime.java`、`subagent/SubagentRuntime.java`：
  仅补齐必要的生命周期、身份、实际用量与压缩展示观察，不改变执行决策。
- `team/TeamManager.java`、`process/BackgroundManager.java`：仅在现有观察点不足时补状态快照，
  不改派工、投递、必等行为或退出归属。

- `llm/ModelResponse.java`、`llm/AnthropicSdkLlmClient.java`：仅在区分已报告／缺省用量所需时

- `pom.xml`：只允许前端必需的依赖，不升级其它能力；Markdown／字素处理优先使用成熟实现，
  锁定版本并记录依据，不自行重造完整解析器。

## Java 架构与所有权

- `tui.terminal`：TerminalSession 管原始模式、读写与恢复，InputDecoder 生成完整输入事件。
- `tui.text`：StyledLine、Span 和 DisplayWidth 表示文本与可见列宽，不掺入业务对象。
- `tui.theme`：不可变 Theme 及具名样式取色，只负责配色，不知道用户配置路径。
  实现时将原拟议 ThemeToken／Themes 收敛在 Theme 内，没有为少量配色再拆枚举与工厂。
- `tui.core`：Component、RenderContext、Frame、InlineRenderer 和 RenderScheduler。
  Frame 同时保存文本、光标与点击区域，布局组合必须一起移动这三类数据。
- `tui.components`：Editor、Markdown、SelectList 和 VerticalStack，均不认识 Agent。
- `cli.tui`：TuiApplication 管生命周期与单一界面循环，TuiController 处理事件及用户意图，
  TuiState 是唯一的界面数据；ConversationView 等负责消息、工具、审批、状态和页脚。
  TuiPreferences 独占前端配置路径和保存逻辑。
- `cli.tui.bridge`：ExecutionUiBridge 转换结构化执行通知，StreamingAdapter 实现 ResponseStream，
  ApprovalBroker 实现 Approval，RoutingPrintStream 仅兜底已有直接打印。
- `cli.plain`：run 的非交互输出与必要文本审批，不启动 TUI 或旧交互编辑器。
- `execution`：新增只读 ExecutionObserver／ExecutionNotice，Agent 和 Session 不导入 CLI。

依赖方向为 `cli.tui → 通用 TUI` 和 `cli.tui → Session／execution`。
通用组件依赖 core／text，core 使用 theme／text，theme 使用 text；terminal 独立提供底层输入输出，
不反向引用业务或组件，不形成相互依赖。
ResponseStream 专管增量，ExecutionObserver 补足工具与运行状态，两者最终进入同一个 UiEvent
队列，不重复发送同一正文。权限 hook 仍拥有检查权，观察器只有通知能力。

界面事件不可携带可被界面误改的执行参数。审批申请在 Broker 内关联 future，界面仅收到
申请编号和显示快照，再由 Broker 按编号完成对应申请。执行线程等待，界面线程不等待。
submitUser／promoteUserBuffer 仍是用户任务入口，TUI 不复制业务缓冲或改写模型历史。

旧 TerminalDisplay、ConsoleInput、CliOutput、CliHooks 的交互职责迁走后删除；run 的
文本能力进入 plain，不以复用为由留下旧交互入口。类名可以在编码时收敛，但职责与依赖不变。

## 源码核对发现的接入问题

以下记录实施前核对的差异，对应处理结果见交付记录；不是把 Pi 的全部功能搬入 JadeCode：

- Pi 默认显示思考，Ctrl+T 全局隐藏／显示；工具默认折叠，Ctrl+O 全局展开／折叠。
  通用工具预览取前十行，自定义工具显示不一定使用相同规则。单卡点击依赖鼠标，不能假设
  Pi 还提供了键盘逐卡选中机制。
- Pi 的 Ctrl+C 首次清空输入，500ms 内再次按下退出；Esc 才用于中止运行或取消当前选择。
  JadeCode 目前的 Ctrl+C 会退出整个会话，没有现成的独立单轮取消接口。若采用 Pi 的
  Esc 行为，会需要运行时修改；Q7 已裁决本次不引入单轮中止。
- JadeCode 的 TURN_END 只在正常完成时触发，失败和关闭不保证触发，不能单靠该 hook
  结束“正在工作”的显示。
- 工具被拦截、工具未知或批次抛异常时，不保证存在 POST_TOOL_USE；已有 POST 参数也没有
  Pi 那样的结构化 isError。不得把所有正常返回的字符串都显示成业务成功。
- 一次性子代理复用父 Hooks 和 ExecutionContext。仅靠工厂中的 Leader／Teammate 前缀
  不能准确识别其工具来源；还要避免 PRE／POST 与 SUBAGENT_TOOL 重复显示同一次调用。
