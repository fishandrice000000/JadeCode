## 相关问题调查（尚未修改行为）

### 记忆整理 INVALID_RESPONSE

这次文字来自 MemoryConsolidationService，不是 MemoryExtractionService。
此前对提取的围栏容错、截断判断、固定原因说明和可配置输出额度没有迁到整理服务。
当前整理固定请求 3000 输出 token，要求返回整库（最多 30 项），回复仅接受裸 JSON 数组。
非法块、空/非数组/超条数、缺字段或类型非法、名称映射后冲突等统一返回 INVALID_RESPONSE，
且不保存该次失败的细分原因；因此不能凭用户这条旧警告证明具体是哪一项。
临时假模型分别返回带完整围栏的合法数组、截断 JSON、缺字段数组，三者都复现同一状态，
且旧库保持不变；相同合法数组去掉围栏后可以发布。这说明日志缺乏区分度，不证明真实模型
那次必然返回了围栏。3000 token 太紧只是可解释的风险，不是已证实的那次失败原因。

安全性：候选非法时不会用半份结果覆盖旧库；整理失败不会撤销提取阶段已经成功新增的记录。
建议后续单独补整理专属输出额度与固定原因分类，识别 stop_reason，允许覆盖全文的一层 JSON 围栏；
继续拒绝残缺整库、尾随文本和非法候选，不通过隐藏 Warning 伪装成功。

### 自动压缩提前触发

ContextCompactor.smallEnough 只比较序列化消息字符数和 contextCharLimit；生产装配传入的是
settings.limits，没有把 client.metadata 的窗口或最近正式请求的 usage 传给触发判断。
本机非秘密设置核对为 300000 字符、自动摘要开启；状态栏的 ContextUsage 则用实际 token
报告计算最近响应的剩余比例，两者独立。缓存参数含 1048576 token 窗口，但缓存存在不代表
本次启动必然使用有效缓存，亦不能把 300000 字符直接换算成 300000 token。

建议以实际模型窗口和请求用量作为自动摘要依据，并预留输出和新增输入的空间；
缺少可靠数据时才回退字符预算。摘要输入的 400000 字符上限也需一起考虑，不能只抬触发阈值
却让摘要提前丢弃中间内容。本调查不宣称已经实现自适应。
