# 修复 TUI 核查清单中的已确认问题

日期：2026-10-20；起点：4c2470f。用户现已授权修复此前只留档的 TUI Bug。
原始证据见 [核查记录](tui-audit-and-turn-status.md)；已有计时、resume 列表与底部定位保持不变。

## 本次范围

1. 审批理由、参数及长期授权范围可逐行/逐页滚动，明确显示当前范围与总行数。
   ↑↓、PgUp/PgDn、Home/End 阅读，←→/Tab 选项，Enter 确认；没有默认答复。
   不强迫用户读完每页，但不能静默截断，也不能从缩短后的显示文本执行操作。
   窗口不足以容纳完整按钮及阅读区时明确要求扩大，不提供可批准的动作。
2. Markdown 代码、引用、列表每条续行保留竖线或缩进，嵌套列表不粘成双项目符号。
3. 代码块只去掉解析器保留的一个终止换行，保留用户刻意写下的额外空行与空格。
4. 页脚不加入空字段，消除启动时的前导分隔符。
5. 标题、提示、目录与候选截短时显示省略号；窄屏页脚优先保留 /help。
6. Tab 补完命令后收起候选，不自动执行；下一次编辑可重新显示。
7. 选择器的光标随选中项和列表窗口移动。

不修改记忆/压缩/调度/权限决策，不改真实用户配置、不调用真实 API，不新增永久单元测试。
鼠标捕获关闭和旧内容重排时清 scrollback 是此前确认的产品取舍，不按 Bug 强改；
Frame.Hit 仍用于确认审批确实已经显示，不能为了删除鼠标分支而移除安全检查。

## 代码组织与失败契约

- ConversationView：独立审批布局、页大小计算、窄屏提示、页脚省略及选择器光标。
- TuiState/TuiController/HistoryViewMapper：申请专属阅读偏移、新队首重置及按键；不改审批答复绑定。
- InputDecoder：识别 PageUp/PageDown，不把转义序列的尾部塞进草稿。
- InlineRenderer：尺寸变化事件立即使旧确认位置失效，等新画面实际绘制后再启用；
  不允许同一批事件中的 Enter 在缩小窗口后继续使用旧按钮的可见记录。
- Markdown：首行/续行前缀分开，正文先换行再补标记；表格保留既有网格与窄屏降级。
- DisplayWidth.ellipsize 独立于 take，保持精确裁列、字素与 ANSI 清理契约；SelectList 共享窗口起点。

实现附中文 JavaDoc 和关键步骤注释。验证包括构建、原有权限/执行回归、临时格式探针、
