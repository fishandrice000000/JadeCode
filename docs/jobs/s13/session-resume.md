# 会话保存、恢复与工作区数据目录整理

## 1. 目标与范围

在现有 SessionRuntime 单消费者架构上保存正式采用的历史，支持
`jade repl --resume [uuid]` 与 `/resume [uuid]`。恢复后等待新输入，不重跑旧工具、
不恢复后台进程、排队输入、审批授权或常驻队友。系统提示、工具与权限采用当前环境。

工作区运行数据统一到 `.jadecode/`；机器级 `~/.jadecode`、`.env`、Git、IDE 与
外部 Agent 配置不迁移。WorkspacePaths 放 config，旧数据迁移放 bootstrap，
不增加 workspace 包，不重构无关模块。

## 2. 存储与数据流

- `.jadecode/sessions/<uuid>/{session.json,events.jsonl,session.lock}`：主会话元数据、顺序日志与 OS 写锁。
- `.jadecode/{tasks,memory,transcripts,tool-results,teams,approvals/backups,cron}`：已有能力的数据。
- SessionRuntime 记录追加、末条替换、压缩/回滚整表替换和实际 Todo 快照；不记录逐 token 增量。
- SessionStore 负责列表与文件；SessionLoader 顺序重建模型历史、Todo 与显示记录。
- CLI SessionHost 管理当前打开的运行时；选择和历史显示由 TUI 完成。
- 压缩前记录保留在日志/显示历史中，模型只接收重建后的有效历史。

## 3. 安全、迁移与失败契约

1. 会话 ID 严格使用 UUID，同一会话只能有一个日志写者；锁文件存在不代表持有锁。
2. 工具执行不参与日志重放。末尾缺少结果时补“结果未记录，操作可能已执行”，不假称未执行。
3. 中间损坏拒绝恢复。尾部半行先保留恢复副本、处理无效尾部，再允许续写。
4. 日志故障保留已得内存结果、禁止开始后续动作并明显告警，不静默冒充可恢复。
5. 目录迁移不覆盖冲突目标、不机械修改历史正文；保留旧引用的读取兼容与迁移说明。
6. 新目录新增一层时同步检查父目录软链接，不降低现有记忆/任务/定时与代审批检查。
7. 切换不取消正在执行的任务：有活动、排队工作、未收后台结果或存活队友时明确拒绝。
   在队列锁内冻结后才关闭旧会话；显示事件按会话代次隔离，防止旧输出串入。
8. 加载和校验目标失败时保留原会话。关闭日志与释放锁须与最后一次日志采用互斥。
9. 现有压缩快照不自动冒充完整会话；迁移/恢复不自动运行模型。持久 cron 的新投递仍属原机制。

- 扩展跨进程检查首次失败：同 JVM 第二次打开锁文件后关闭通道，会释放系统上的原有锁。

  修复后重复打开拒绝与跨 JVM 拒绝同时通过。该平台行为也见
  [JDK 21 FileLock 文档](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/channels/FileLock.html)。
- 自审修正：旧工具卡不再参与新调用 ID 查找；压缩后的通知只显示新增部分，不能覆盖旧显示正文；
  失败记录本身写盘失败仍完成 future；关闭/失败时不继续采用迟到回复；清单可由日志重算。
- 最终 PTY 还验证了启动选择器筛选与 Enter 选中，恢复后新轮次确实写入原日志；
  非 UUID CLI 参数在启动终端/加载认证之前返回退出码 2。

## 8. 明确未实现和未验证的部分

- 不恢复排队输入、线程、后台进程、队友运行时、审批授权或旧环境设置，不重放工具。
- 不把旧 transcript 快照自动转换成从未保存过的完整对话。不支持跨工作区/工作树、分支或自动续跑。
- 历史卡片重建主消息与工具交换，不恢复完整的队友/子代理显示过程或旧用量/耗时。
- 单日志加载/追加上限 256 MB，无自动清理/无限大日志流式加载；文件强制写入不等于断电事务。
- 文件锁只约束协作写者，不是数据目录防篡改沙箱；工作区 cron/任务图仍不承诺多进程并发写。
- 本仓库原有运行数据未在开发期间主动移动，避免碰到用户尚在运行的旧进程；
  用户退出旧版后，下次启动由迁移器执行。临时工作区中的迁移已验证。
- 用户原有文档/笔记改动和 docs/reviews/ 保持不动，不暂存、不提交。
