# s13：整理多 Agent 的终端展示

## 需求与范围

用户真机验证了首次派工、同一队友复用与 blocked 报告，随后要求先美化终端。
当前困难是工具和轮次没有来源、回复与通知挤在一起、计划块过于突兀，不是 Team 消息没送到。

本轮只改变展示：

- Leader 与队友的回复、工具、计划、轮次和运行错误使用同一份来源前缀。
- 回复、计划、审批分段；工具和通知保持短日志；文件工具显示单行路径摘要。
- 保留模型回复正文，不实现不完整的 Markdown 解析器，不改模型收到的历史。
- 同一个真实终端共用输出流，显示完整多行输出后再由 JLine 恢复用户输入。
- 颜色按实际终端支持决定，尊重 NO_COLOR / TERM=dumb；管道不产生色码或输入提示符。
- Enter、Alt+Enter、多行粘贴、用户缓冲升级、y/n 审批及关闭行为保持原契约。

不改任务状态、消息优先级、权限判断、Memory、模型协议或流式传输，不调用真实模型。
SDK 的“跳过未知响应块”仍是 OPT-004；任务说明错误 ID 记入 OPT-005，本轮不修。
不处理用户已有笔记、删除项或 docs/reviews。

## 实现组织

1. JadeCodeFactory 的 Presentation 安装函数接收本会话 output，工厂不依赖 CLI。
2. CliHooks 用该 output 显示消息；CliOutput 负责标题、颜色和完整块打印。
3. TerminalDisplay 继续负责唯一的输入读取器与输入重画，Ansi 负责颜色降级。
4. README 只补充显示规则；另附可选的终端展示阅读说明，不重写章节学习材料或用户答案。
