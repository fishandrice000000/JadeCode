# 权限、输入与记忆可靠性修复

日期：2026-10-20。用户授权核实 JadeCode 的审查并修复本轮及上一轮问题，按模块创建本地小提交。

## 范围与契约

1. Shell：正确解释未加引号的 `~/`，保留加引号/转义后的字面意义；不执行展开命令。
   不确定原因必须具体；不通过关闭权限检查解决重复审批。工作区外访问仍遵守原档位。
2. 输入与审批：审批使用独立配色；Ctrl+左右按词移动，不拆 emoji 或折叠粘贴。
3. 轮次计时：扣除所属轮次实际等待人工审批的时间，包含审批排队；实时与最终采用同一口径。
   辅助模型审批、普通模型请求和后台等待不暂停。不同 Agent 的时间不互相扣减。
4. 记忆文件：坏编码按条跳过；名称长度受 UTF-8 字节预算约束，归一化碰撞不丢掉不同名称；
   同名跳过与坏候选分别计数。库操作使用进程内互斥与文件锁，防止派生索引丢失更新。
5. 整理发布：先持久保存原库和候选，再替换；保留备份，发现未完成发布时恢复原库。
   恢复不覆盖未知外部修改，不宣称防恶意竞态或任意硬件故障。
6. 记忆模型：输出预算和输入预算可配置，识别截断/拒绝/格式错误；允许完整 JSON 围栏，
   不从杂文里猜数组，不用残缺整理结果覆盖原库。召回覆盖所有目录页，不永久偏向文件名前缀。
   使用真实 `.jadecode/memory/` 来源；所有诊断走注入通道，避免泄露模型正文与秘密。
7. 辅助记忆的普通运行期异常不能吞掉主任务回答；不捕获 JVM Error，不把维护失败说成成功。

## 审查结论的修正

- 输入超过 20000 字符会使当前库无法进入整理，不代表一切输入永远不能整理。
- 固定 3000 tokens 偏紧，但仅凭字符数不能证明每次必然截断；以 stopReason 为准。
- 固定目录前缀确会排除尾部；能容纳多少条取决于实际条目长度，不固化“33 条”。
- 同名不覆盖原本是有意契约；不同名称因归一化相同而被跳过需要修复。
- 本轮不新增永久单元测试。使用临时文件库、假模型、按键与显示探针，以及已有定向测试。
- 清空记忆命令、将维护改成异步任务属于额外产品设计，不从审查中的 Question 自动扩展实施。
