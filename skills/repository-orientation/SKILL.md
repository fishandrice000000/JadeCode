# Repository Orientation

以仓库事实为准建立项目地图。优先阅读 README、pom.xml、源码目录、测试目录和程序入口，再沿关键调用链查看必要文件。

输出应让读者快速回答：

- 程序从哪里启动，主要对象如何装配；
- 核心模块各自负责什么，依赖方向如何；
- 一次典型请求经过哪些关键阶段；
- 测试按什么层次组织，新增行为通常应落在哪里；
- 文档与实际代码是否存在漂移。

保持简洁，只展开理解当前问题所需的部分。引用具体文件路径；不运行会改变仓库或外部状态的命令，也不修改文件。
